## Non-Functional Requirements

**Rendering (P0):**
- [x] All components must render correctly in SSR and WASM
- [x] No hydration mismatches on initial render
- [x] Components use core.Node interface, not direct js.Value

**Styling (P0):**
- [x] Tailwind CSS utility classes only
- [x] No additional CSS frameworks
- [x] Consistent design tokens (colors, spacing, typography)

**Performance (P1):**
- [x] WASM bundles < 5MB per route bundle
- [x] Event handlers properly cleaned up to prevent memory leaks
- [x] No blocking operations in render path

**Developer Experience (P1):**
- [x] Props structs for all components (no interface{})
- [x] Clear prop naming conventions
- [x] Components work with hot reload

## Constraints

- [x] **No backwards compatibility** — fresh implementation on core.Node
- [x] **Tailwind CSS only** — no DaisyUI or other Tailwind plugins
- [x] **Core auth flows only** — no OAuth, 2FA, magic links
- [x] **Focused examples** — 5-10 pages each, not complete products

## Acceptance Criteria

1. [x] Component library provides all P0 components listed above (26/32, 6 deferred)
2. [x] Each example app runs standalone with `gux dev`
3. [x] All examples demonstrate SSR + WASM hydration
4. [x] No TypeScript/JavaScript required to build examples
5. [x] Components render identically in SSR and WASM
