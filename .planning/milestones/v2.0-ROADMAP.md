# v2.0 Core Components — Milestone Roadmap

## Milestone Goal

Build a fresh component library on core's Node system with four example applications demonstrating real-world use cases: marketing site, SaaS dashboard, admin panel, and auth flows.

## Key Decisions

| Decision | Rationale | Outcome |
|----------|-----------|---------|
| Fresh component library | Core's Node architecture is fundamentally different from old js.Value approach | — Pending |
| Shared foundation across examples | Reduces duplication, shows realistic patterns | — Pending |
| Tailwind CSS only | Consistency, no framework mixing | — Pending |
| Core flows for auth (no OAuth) | Keep scope manageable for v2.0 | — Pending |

## Phases

### Phase 16: Component Foundation
**Goal:** Establish patterns and base primitives before building component library

**Delivers:**
- Utility functions (mergeClasses, conditionalAttr)
- Button with variants (primary, secondary, outline, ghost, destructive) and sizes
- Card with header/content/footer composition
- VStack/HStack layout primitives
- Container with max-width
- Props struct patterns documentation

**Success criteria:**
- [ ] Button renders correctly in SSR and WASM
- [ ] Card composition pattern works with children
- [ ] Layout primitives handle gap and alignment
- [ ] No interface{} in props

**Dependencies:** None
**Research needed:** No (patterns exist in codebase)

## Risk Mitigation

**WASM Memory Leaks (CL-4):**
- Address in Phase 19 with callback cleanup patterns
- Document cleanup requirements for all stateful components

**Binary Size (GW-1):**
- Monitor bundle sizes during development
- Use existing multi-bundle architecture
- Defer TinyGo optimization to production

**Hydration Mismatches (HY-3):**
- Test all components in both SSR and WASM
- Avoid time-dependent or random values in render
