# Milestone v2.3: gux help Patterns

**Status:** ✅ SHIPPED 2026-01-26
**Phases:** 28
**Total Plans:** 2

## Overview

Add `gux help <pattern>` commands that output boilerplate code for developers and LLMs working in established gux projects. A small, focused milestone delivering 7 help commands with go.mod integration and proper output formatting.

## Phases

### Phase 28: Help Pattern Commands

**Goal**: Developers can run `gux help <pattern>` and get correct, copy-pasteable boilerplate code
**Depends on**: Phase 27 (gux init templates established patterns to reference)
**Plans**: 2 plans

Plans:
- [x] 28-01-PLAN.md - Help command infrastructure and go.mod reading
- [x] 28-02-PLAN.md - Pattern templates (page, page:list, page:form, model, dto, routes, app)

**Details:**
- Created help.go with Pattern struct and pattern registry map
- Added getModulePathForHelp() using modfile.ModulePath for tolerant go.mod parsing
- Added printPatternList() for sorted alphabetical pattern listing
- Added runHelpPattern() for template rendering with module path substitution
- Integrated help command routing in main.go
- Added 7 pattern templates with copy-pasteable Go code
- Split `gux help` (shows patterns) from `gux -h` (shows usage)

## Milestone Summary

**Key Decisions:**
- Used getModulePathForHelp() to avoid collision with existing getModulePath in build.go
- Used modfile.ModulePath() for tolerant parsing (handles malformed go.mod files gracefully)
- Used string concatenation for backticks in Go struct tags to avoid template escaping issues
- Split `gux help` (shows patterns) from `gux -h/--help` (shows usage) for better UX

**Issues Resolved:**
- Fixed 'gux help' to show patterns instead of usage (was calling printUsage() instead of printPatternList())

**Issues Deferred:**
None

**Technical Debt Incurred:**
- Help templates duplicated from scaffold templates rather than sharing a source (minor DRY violation)
- Minor cosmetic differences between help templates and scaffold templates (arrow in "Back to Items" link)
