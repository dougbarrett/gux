# Roadmap: v2.3 gux help Patterns

## Overview

Add `gux help <pattern>` commands that output boilerplate code for developers and LLMs working in established gux projects. A small, focused milestone delivering 8 help commands with go.mod integration and proper output formatting.

## Milestone Goal

Developers can run `gux help <pattern>` and get correct, copy-pasteable boilerplate code with the right module path and file location hints.

## Phase Details

### Phase 28: Help Pattern Commands

**Goal**: Developers can run `gux help <pattern>` and get correct, copy-pasteable boilerplate code

**Depends on**: Phase 27 (gux init templates established patterns to reference)

**Requirements**: HELP-01, HELP-02, HELP-03, HELP-04, HELP-05, HELP-06, HELP-07, HELP-08, MOD-01, MOD-02, MOD-03, OUT-01, OUT-02, OUT-03

**Success Criteria** (what must be TRUE):
1. Running `gux help` shows all available patterns with brief descriptions
2. Running `gux help page` (and page:list, page:form, model, dto, routes, app) outputs valid Go code for that pattern
3. Output uses the correct module path from go.mod (or placeholder with warning if missing)
4. Output includes file path header comment showing where to save the code
5. Output code compiles without modification when pasted into the correct location
