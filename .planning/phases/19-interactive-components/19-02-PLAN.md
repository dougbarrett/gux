  <action>
Create Tooltip component following research patterns in 19-RESEARCH.md.

**Tooltip types and constants:**
- TooltipPosition string type with constants: TooltipTop, TooltipBottom, TooltipLeft, TooltipRight
- tooltipPositionClasses map for positioning (each position needs specific classes)

**Position classes (use negative translate for offset):**
- TooltipTop: "bottom-full left-1/2 -translate-x-1/2 mb-2"
- TooltipBottom: "top-full left-1/2 -translate-x-1/2 mt-2"
- TooltipLeft: "right-full top-1/2 -translate-y-1/2 mr-2"
- TooltipRight: "left-full top-1/2 -translate-y-1/2 ml-2"

**TooltipProps struct:**
- Content string (tooltip text)
- Position TooltipPosition (default: TooltipTop)
- Class string (additional classes for wrapper)
- Children []core.Node (the trigger element(s))

**Tooltip function:**
- Wrapper div with "relative inline-block group" (group enables group-hover)
- Children render first (the trigger)
- Tooltip element renders after children with position: absolute
- Tooltip base classes: "absolute z-50 px-2 py-1 text-sm text-white bg-gray-900 rounded shadow-lg whitespace-nowrap"
- Visibility classes: "opacity-0 invisible group-hover:opacity-100 group-hover:visible group-focus-within:opacity-100 group-focus-within:visible"
- Transition: "transition-opacity duration-200 pointer-events-none"
- ARIA: role="tooltip" on tooltip element
- Default position to TooltipTop if empty

**Note:** This is CSS-only - no JS/WASM state needed. Works in SSR because tooltip is always in DOM but hidden via opacity/visibility.
