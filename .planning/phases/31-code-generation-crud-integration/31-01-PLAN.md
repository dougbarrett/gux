Add file lifecycle hooks, automatic file cleanup, and FileInfo DTO support to the CRUD system.

Purpose: When models have file fields, CRUD operations must automatically manage file storage -- cleaning up files on record delete, cleaning up replaced files on update, and rolling back uploads on DB failure. Developers also need hook points to inject validation (BeforeUpload), post-processing (AfterUpload), and deletion prevention (BeforeFileDelete).

**In `core/storage.go`**, add a `FileInfo` struct after the existing `UploadResult` struct:

```go
// FileInfo represents file metadata exposed in DTOs for file fields.
// Models store a storage key (string), but DTOs expose FileInfo with
// resolved URL and metadata for rendering in admin views.
type FileInfo struct {
    URL         string `json:"url"`
    Filename    string `json:"filename"`
    Size        int64  `json:"size"`
    ContentType string `json:"content_type"`
}
```

This is the struct that generated DTOs will use for file fields (`*FileInfo` instead of `string`). It is intentionally simpler than UploadResult -- no Key, Width, Height. It represents the public-facing file metadata.

Also add a method on Storage interface is NOT needed -- instead, add a helper function that builds FileInfo from a storage key by calling Storage.Serve to get file info:

```go
// FileInfoFromKey builds a FileInfo from a storage key using the Storage interface.
// Returns nil if key is empty. Uses Serve() to get file metadata (size, content type).
// If Serve fails (file missing), returns a FileInfo with just the URL and filename derived from key.
func FileInfoFromKey(s Storage, key string) *FileInfo {
    if key == "" || s == nil {
        return nil
    }
    info := &FileInfo{
        URL:      s.URL(key),
        Filename: extractFilename(key),
    }
    // Try to get full metadata from storage
    reader, fileInfo, err := s.Serve(key)
    if err == nil {
        reader.Close()
        info.Size = fileInfo.Size()
        // Content type detection from filename
        info.ContentType = detectContentType(key)
    }
    return info
}
```

For `extractFilename`, add a helper that extracts the original filename from the storage key. Since Phase 29 uses content-addressed storage (SHA-256 hash filenames), the original filename is NOT in the key. The filename should be derived from UploadResult metadata stored somewhere. However, looking at the current storage implementation, the key IS the hashed filename -- the original filename is only in the UploadResult returned at upload time. For now, `extractFilename` should return the last path segment of the key (the hash-based filename). This is a reasonable default -- the generated admin UI will show the hash-based name but can be enhanced later.

Actually, a simpler approach: since we need the original filename and content type, and these are known at upload time but NOT stored with the file key, we should store the UploadResult metadata alongside the file. But that's a bigger change. For Phase 31, take the pragmatic approach:

- `Filename`: Extract from key (last path segment). Not the original filename, but functional.
- `ContentType`: Detect from file extension using `mime.TypeByExtension` from stdlib.
- `Size`: From `os.FileInfo` via `Serve()`.

Add these helpers:

```go
func extractFilename(key string) string {
    if idx := strings.LastIndex(key, "/"); idx >= 0 {
        return key[idx+1:]
    }
    return key
}

func detectContentType(key string) string {
    ext := filepath.Ext(key)
    if ext == "" {
        return "application/octet-stream"
    }
    ct := mime.TypeByExtension(ext)
    if ct == "" {
        return "application/octet-stream"
    }
    return ct
}
```

Add `"mime"`, `"path/filepath"` to imports.

4. **Add file cleanup helper method on App**:

```go
func (a *App) deleteFileIfExists(model CRUDModel, key string) {
    if key == "" || a.storage == nil {
        return
    }
    if model.OnBeforeFileDelete != nil {
        if err := model.OnBeforeFileDelete(key); err != nil {
            return
        }
    }
    if !model.DisableAutoCleanup {
        ctx := context.Background()
        if err := a.storage.Delete(ctx, key); err != nil {
            fmt.Printf("gux: warning: failed to delete file %s: %v\n", key, err)
        }
    }
}

func getFileFieldValues(item interface{}, fileFields []string) map[string]string {
    values := make(map[string]string)
    v := reflect.ValueOf(item)
    if v.Kind() == reflect.Ptr {
        v = v.Elem()
    }
    for _, fieldName := range fileFields {
        f := v.FieldByName(fieldName)
        if f.IsValid() && f.Kind() == reflect.String {
            values[fieldName] = f.String()
        }
    }
    return values
}
```

Add a helper `populateFileInfoFields` that:
1. Takes a DTO instance, the source model instance, the file fields list, and the storage interface
2. For each file field, checks if the DTO has a field of type `*FileInfo`
3. If so, reads the string value from the source model and calls `FileInfoFromKey` to populate it

```go
func populateFileInfoFields(dto interface{}, model interface{}, fileFields []string, s Storage) {
    if len(fileFields) == 0 || s == nil {
        return
    }
    dtoVal := reflect.ValueOf(dto)
    if dtoVal.Kind() == reflect.Ptr {
        dtoVal = dtoVal.Elem()
    }
    modelVal := reflect.ValueOf(model)
    if modelVal.Kind() == reflect.Ptr {
        modelVal = modelVal.Elem()
    }
    fileInfoType := reflect.TypeOf((*FileInfo)(nil))
    for _, fieldName := range fileFields {
        dtoField := dtoVal.FieldByName(fieldName)
        if !dtoField.IsValid() || dtoField.Type() != fileInfoType {
            continue
        }
        modelField := modelVal.FieldByName(fieldName)
        if !modelField.IsValid() || modelField.Kind() != reflect.String {
            continue
        }
        key := modelField.String()
        info := FileInfoFromKey(s, key)
        dtoField.Set(reflect.ValueOf(info))
    }
}
```
