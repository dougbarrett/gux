# Gux - Full-Stack Go Framework for WebAssembly

> Gux is a full-stack Go framework for building modern web applications with WebAssembly. Write backend and frontend entirely in Go, compile to WASM, and run natively in the browser.

## Project Overview

Gux enables developers to build complete web applications using only Go:
- Type-safe API clients and server handlers via code generation
- Universal rendering framework (SSR + WASM)
- CRUD API generation with DTOs and hooks
- CSRF protection enabled by default
- Compiles to WASM for client-side interactivity

## Key Concepts

### Build Targets
- **WASM packages** (core/dom_renderer.go, fetch): Use `//go:build js && wasm`
- **Server packages** (api, server, core/html_renderer.go): Standard Go, no build tags
- **Universal packages** (core): Compile for both with conditional platform files

### Code Generation (apigen)
Define API interfaces with annotations:
```go
// @client PostsClient
// @basepath /api/posts
type PostsAPI interface {
    // @route GET /
    List(ctx context.Context, page, perPage int) (*PaginatedResult[Post], error)
    // @route POST /
    Create(ctx context.Context, post *CreatePost) (*Post, error)
    // @route GET /{id}
    Get(ctx context.Context, id string) (*Post, error)
}
```

Generate with: `go run ./cmd/apigen -source=api/posts.go -output=posts_client_gen.go`

### State Management
State is managed via the core.Router:
```go
count := r.StateInt("count", 0)       // int state
name := r.StateString("name", "")     // string state
user := core.UseState(r, "user", User{}) // any type

// Read and update
current := count.Get()
count.Set(current + 1)
```

### CRUD Pattern
Automatic REST API generation with DTOs:
```go
app.CRUD(models.User{},
    core.WithListDTO(dto.UserList{}),
    core.WithDetailDTO(dto.UserDetail{}, "Posts"),
    core.WithCreateHook(func(data map[string]interface{}) (interface{}, error) {
        // Custom creation logic (e.g., password hashing)
    }),
)
```

## Conventions

1. **Error Handling**: Use structured errors from `api/errors.go` (NotFound, BadRequest, etc.)
2. **Middleware**: Compose with `server.Chain(middleware1, middleware2, ...)`
3. **DTOs**: Define separate structs for list/detail views to control API exposure
4. **CSRF**: Automatically enabled for all mutating operations (POST/PUT/PATCH/DELETE)
5. **Path Parameters**: Use `:id` syntax in route definitions

## Common Tasks

### Add a new CRUD resource
1. Define model in `models/` directory
2. Create DTOs in `dto/` directory for list/detail views
3. Register CRUD in app.go:
   ```go
   app.CRUD(models.MyModel{},
       core.WithListDTO(dto.MyModelList{}),
       core.WithDetailDTO(dto.MyModelDetail{}),
   )
   ```

### Add a new page
1. Create page function in `pages/` or `admin/` directory
2. Define loader with `r.OnLoad()` for data fetching
3. Return component function for rendering
4. Register route in app.go:
   ```go
   app.Routes().Hybrid("/mypage", pages.MyPage)
   ```

### Add state to a page
```go
count := r.StateInt("count", 0)
count.Set(count.Get() + 1)
```

## Architecture Notes

- Universal rendering: Same code renders on server (SSR) and client (WASM)
- Server uses standard net/http with middleware composition
- CRUD generation ensures type-safety between client and server
- Hybrid routing: SSR on first load, WASM hydration for interactivity
- CSRF protection automatic via Double Submit Cookie pattern
- DTOs control data exposure - hide sensitive fields (passwords, etc.)
